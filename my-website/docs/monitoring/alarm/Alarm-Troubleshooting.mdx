# Alarm Configuration {#top}

Use this guide to **create and manage alarms** that trigger when conditions are met (for example, a metric threshold breach), then **notify the right people** through the right channels—without causing alert fatigue.

If you opened this page from in‑product help, jump to:

- **Create an alarm** → Procedure
- **Alarm not firing** → Troubleshooting
- **Notification issues** → Notification channels

## At a glance {#at-a-glance}

- **Primary task:** Define an alarm rule, set sensitivity, and configure notifications.
- **Typical users:** Operators, SRE/DevOps, admins.
- **Common entry points:** Alarms list, New Alarm wizard, Rule builder, Notification settings.
- **Common problems covered:** Invalid rule, missing notification channels, alarm suppressed, delayed evaluation.

## Prerequisites {#prerequisites}

Before configuring alarms, ensure:

1. You have access to the **Monitoring** module and **Alarms** page.
2. The target resource (service/host/device/app) exists and is sending data.
3. At least one **notification channel** is configured (email, Teams, webhook, etc.).
4. Your role includes **Manage Alarms** permission (or equivalent).

<Admonition type="tip" title="Tip — Avoid alert fatigue">
  Start with fewer alarms and tune thresholds and duration over a week. Use severity levels and routing to reduce noise.
</Admonition>
